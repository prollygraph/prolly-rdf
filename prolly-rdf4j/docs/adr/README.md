
# Architecture Decision Records

Significant decisions about prolly-rdf4j's architecture, with the context
and alternatives that were considered. New ADRs go in this directory
with a sequential numeric prefix: `NNNN-short-title.md`.

Use ADRs for decisions that meet **any** of:

- Touch on-disk format or wire protocol
- Pick between two or more viable approaches with materially different
  tradeoffs (performance, complexity, compatibility)
- Land a feature whose later revisitation cost is high (schema change,
  API surface, security model)

Don't ADR for routine bug fixes, refactors, or minor UI choices —
those belong in the PR description.

## Format

Each ADR should answer four questions, in roughly this order:

1. **What's the problem?** Context and constraints.
2. **What are the options?** At least 2-3 alternatives with explicit
   tradeoffs in a comparison table.
3. **What did we pick, and why?** The decision, with rationale that
   names the deciding tradeoff(s).
4. **What does it cost?** Consequences — performance impact,
   compatibility breaks, follow-up work, what we're punting.

Open questions that need stakeholder alignment go in a final section
so they're easy to spot before implementation begins.
